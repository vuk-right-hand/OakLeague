## 2026-04-21 — Spike A Phase 0: Gemini Live WS is binary protobuf, not JSON

Root cause: raw WS to `v1alpha.BidiGenerateContentConstrained` sends back **binary** frames (`setupComplete` arrived as 26-byte binary frame ~770ms post-setup, not JSON text). Hand-rolled `JSON.parse(event.data)` parsers see zero text frames.
Fix: use `@google/genai` SDK `ai.live.connect({ model, config, callbacks })` client-side — SDK decodes binary → `LiveServerMessage` object. Token mint stays server-side; client instantiates `new GoogleGenAI({ apiKey: token.name, httpOptions: { apiVersion: 'v1alpha' } })`. Plan updated Phase 3 accordingly.
Lesson: Gemini Live wire format is binary protobuf. Always prefer SDK Live client over raw WebSocket unless you're writing a protobuf decoder.

## 2026-04-21 — Spike A Phase 0: setup frame confirmed required (server says so)

Root cause: skipping the setup frame on `BidiGenerateContentConstrained` closes the WS with code 1007, reason `"setup must be the first message and only the first"`. `liveConnectConstraints` at mint time does NOT replace the setup frame — it constrains its allowed shape.
Fix: SDK sends setup automatically via `ai.live.connect({ config })`. If writing raw WS, first frame MUST be `{ setup: {...} }` with values consistent with mint-time constraints.
Lesson: constrained-token "locking" is post-validation, not pre-population.

## 2026-04-21 — Spike A Phase 0: 2.5 native-audio is GA on AI Studio v1alpha (not Vertex-only)

Root cause: concern that `gemini-live-2.5-flash-native-audio` might be Vertex-only. Token mint with that model on AI Studio v1alpha succeeded first try.
Fix: plan's 2.5-Vertex-branch is dead code — delete from Phase 4 decision tree. 3.1 → 2.5 flip is env-var only, no Vertex migration.
Lesson: verify availability with a real mint, not docs. Saves 30min of dead planning.

## 2026-04-21 — Creator dashboard: SSRF port check order, slugify regex, stale-session deletes

Root cause: four independent bugs — (1) port check needed to block non-443 probes; (2) slugify `/[^a-z0-9_-\s]/g` dash position created ambiguous range, stripping spaces; (3) `deleteTopic`/`deleteSampleContent` used `supabaseServer()` so a stale cookie silently aliased owned-row deletes to `not_found`; (4) `BrainStatusBadge` never reset exponential backoff after a transient error.
Fix: (1) `assertSafePublicHttpsUrl` now whitelists `port === '' || '443'` (validate-url.ts); (2) regex → `/[^a-z0-9_\s-]/g` (brain-ui.tsx:27); (3) delete actions switched to `supabaseAdmin()` + explicit `creator_id` filter (actions.ts); (4) `delayRef.current = POLL_INITIAL_MS` on success (BrainStatusBadge.tsx).
Lesson: for delete actions, use admin client with explicit ownership filter — RLS second-wall is bypassed by stale cookies and silently produces 0-row results that look like 404s.

## 2026-04-21 — Creator topics trigger 0039 has a hooks-branch with no dashboard remediation path

Root cause: migration 0039 raises `topic_referenced_by_hooks` if a topic slug appears in `hooks.topic_tags`. hooks/videos tables exist but no hooks publisher UI exists yet, so in practice no hooks rows exist. Error surfaces as an undeleteable topic with no fix path in the dashboard.
Fix: none needed today (0 hooks rows). When hooks publisher ships, add "remove hook" UI before deleting topic, or add a cascade option.
Lesson: BEFORE DELETE triggers that reference v2 tables should be documented here. Whoever ships the hooks publisher inherits this constraint.

## 2026-04-21 — Spike A Phase 0: @google/genai access path is `ai.authTokens.create`, not `ai.tokens.create`

Root cause: SDK `genai.d.ts` docblocks (L10359 etc) say `ai.tokens.create(config)` but the actual class property on line 5357 is `readonly authTokens: Tokens`. `ai.tokens` is undefined.
Fix: always reference `client.authTokens.create(...)`. Ignore SDK docblock examples.
Lesson: when SDK examples and type declarations disagree, the type declaration wins. Grep for `readonly \w+:` on the client class.
